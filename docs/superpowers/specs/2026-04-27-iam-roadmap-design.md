# IAM 模块功能补全路线图

## 1. 背景

基于 `go-iam` 项目分析，当前 `apps/iam` 存在以下功能缺失：

| 功能类别 | 缺失项 |
|---------|--------|
| OAuth2/OIDC 认证 | 第三方登录 (GitHub/Microsoft/OIDC) |
| 客户端认证 | Client Credentials |
| 资源管理 | Resource CRUD |
| 策略管理 | ABAC 动态策略 |
| 认证提供商 | 第三方 OAuth 提供商配置 |
| 用户高级功能 | 所有权转移、资源复制 |
| 基础设施 | 加密服务独立化 |

## 2. 功能路线图

### Phase 1: 基础安全能力

| 序号 | 功能 | 工期 | 说明 |
|------|------|------|------|
| 1.1 | **OAuth2/OIDC 第三方登录** | 中 | 支持 GitHub/Microsoft/通用 OIDC 登录 |
| 1.2 | **Client Credentials 认证** | 小 | 服务间 API 认证 |

### Phase 2: 权限增强

| 序号 | 功能 | 工期 | 说明 |
|------|------|------|------|
| 2.1 | **ABAC 策略管理** | 大 | 参数化动态策略，支持属性条件 |
| 2.2 | **认证提供商管理** | 中 | 独立配置第三方 OAuth 提供商 |

### Phase 3: 资源管理

| 序号 | 功能 | 工期 | 说明 |
|------|------|------|------|
| 3.1 | **Resource CRUD** | 中 | 资源的创建/查询/更新/删除 |
| 3.2 | **资源权限分配** | 中 | 用户-资源-角色关联管理 |

### Phase 4: 高级功能

| 序号 | 功能 | 工期 | 说明 |
|------|------|------|------|
| 4.1 | **所有权转移** | 小 | 用户间资源所有权转移 |
| 4.2 | **资源复制** | 小 | 源用户资源复制到目标用户 |
| 4.3 | **加密服务独立化** | 小 | 对称加密服务抽取为独立模块 |

## 3. 依赖关系

```
[1.1 OAuth2/OIDC] ──┬── [2.2 认证提供商管理]
                    │
[1.2 Client Cred] ──┘
         │
         ▼
[2.1 ABAC 策略] ←─── 独立
         │
         ▼
[3.1 资源管理] ──── [3.2 资源权限分配]
         │
         ▼
[4.X 高级功能]
```

## 4. 推荐实施顺序

**推荐：Phase 1 → Phase 2 → Phase 3 → Phase 4**

- Phase 1 和 Phase 2 可并行开发（无依赖）
- Phase 3 依赖 Phase 2 的策略能力
- Phase 4 为可选高级功能

## 5. 优先级评估

| 优先级 | 功能 | 理由 |
|--------|------|------|
| 高 | OAuth2/OIDC | 主流认证方式，用户场景广泛 |
| 高 | Client Credentials | 服务间调用必需 |
| 高 | ABAC 策略 | 细粒度权限控制核心 |
| 中 | 认证提供商管理 | OAuth2 配套功能 |
| 中 | 资源管理 | 数据隔离的基础能力 |
| 低 | 高级功能 | 可选增强功能 |
